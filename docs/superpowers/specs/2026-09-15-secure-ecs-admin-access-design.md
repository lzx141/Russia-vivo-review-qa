# ECS 管理面安全接入设计

## 目标

让 Windows 电脑在公网 IP 变化时仍可直接访问 ECS 上的 Hadoop、YARN 与宝塔管理页面，同时不把这些管理端口暴露给公网，并保留阿里云 Workbench 作为应急入口。

## 当前状态与根因

- ECS 公网地址为 `116.62.152.97`，系统为 Alibaba Cloud Linux 3。
- Hadoop NameNode UI、YARN UI、宝塔面板当前依赖安全组中的客户端公网 IP 白名单。
- 客户端公网 IP 会变化，因此每次变化后旧的 `/32` 规则不再匹配。
- 本机到 ECS 公网 22 端口的非交互 SSH 测试超时，现阶段只能从阿里云 Workbench 执行首次服务器命令。
- 安全组保留了阿里云 Workbench 使用的 `100.104.0.0/16 -> TCP 22` 规则，可作为切换期间和切换后的应急入口。

## 选定方案

使用 Tailscale 建立 Windows 与 ECS 之间的加密私网。Windows 和 ECS 分别安装客户端并登录同一个 tailnet。管理页面通过 ECS 的 Tailscale IP 或 MagicDNS 名称访问，不再依赖客户端公网 IP。

公网业务入口与管理入口分离：

- 保留公网 `80`，后续启用 HTTPS 时增加 `443`，用于公开项目展示页面。
- Hadoop `9870`、YARN `8088`、宝塔 `9160`、MySQL `3306` 不再对互联网开放。
- SSH 公网不新增 `0.0.0.0/0` 规则；保留 Workbench 的 `100.104.0.0/16 -> 22` 规则。
- 不把 ECS 自身公网 IP `/32` 视为客户端访问规则。

## 实施顺序

1. 在 Windows 安装 Tailscale，并完成交互式登录。
2. 用户只在已打开的阿里云 Workbench 中粘贴一次官方安装与启动命令；认证链接在用户浏览器中完成。
3. 记录 ECS 的 Tailscale IPv4，并从 Windows 验证私网连通、SSH 和三个管理页面。
4. 只有全部验证通过后，才删除或禁用公网侧的 `9870`、`8088`、`9160`、`3306` 客户端 IP 规则。
5. 从 Windows 复测私网访问，并从公网地址验证管理端口不可达。

## 验收条件

- Windows 重连网络后，无需修改阿里云安全组即可访问 ECS 管理面。
- `http://<tailscale-ip>:9870`、`:8088`、`:9160` 可按实际服务监听状态访问。
- `ssh hadoop@<tailscale-ip>` 可连接，或至少 TCP 22 私网可达。
- 公网 `116.62.152.97:9870/8088/9160/3306` 不可从普通互联网访问。
- 公网项目页面 `http://116.62.152.97/` 保持可访问。
- Workbench 远程连接仍可用。

## 安全与回滚

- 不在文档或命令历史中保存阿里云账号密码、Tailscale 登录令牌或私钥。
- 不自动点击 ECS 变配付款。
- 不在私网验证前删除任何安全组规则。
- 若私网验证失败，保持原安全组不变；若收口后出现问题，通过 Workbench 恢复对应的原 `/32` 规则。
- 删除规则属于可能造成失联的云权限变更，执行前必须再次展示精确规则并取得用户当次确认。

## 资源升级边界

本设计不要求先升级内存。2 GiB 足以完成网络接入，但当前可用内存仅约 433 MiB；若要运行 Spark/YARN 数据工程任务，升级到 4 GiB 属于合理的独立变更。截图中的 `¥248.270` 是本次变配从当前日期到实例到期日的预估补差，不包含到期后的续费；低价长效活动资格可能受变配影响。

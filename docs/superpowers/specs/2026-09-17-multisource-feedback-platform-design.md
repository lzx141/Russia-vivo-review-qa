# 多源用户反馈可信分析平台设计

## 目标

在不引入机器学习训练、不升级当前 ECS 配置的前提下，将现有俄罗斯跨境电商用户反馈项目重构为可追溯、可复现、具备数据源对照能力的数据分析与数据工程项目。

## 范围

- 修复现有原始数据到合并数据的覆盖问题。
- 建立统一数据契约、稳定商品主键和指标适用性字段。
- 使用 HDFS、Spark 和 Parquet 实现 ODS/DWD/DWS/ADS 分层。
- 接入与当前主题相同或相近的 Wildberries 外部数据子集。
- 实现自主采集与公开数据的匹配样本对照研究。
- 实现旧 Pandas 管道与新 Spark 管道的离线 A/B。
- 将 ADS 结果提供给 MySQL、Notebook 和现有 ECharts 看板。

## 非目标

- 不训练或部署机器学习模型。
- 不将观察性数据源比较称为随机 A/B Test。
- 不下载或保存完整亿级公开数据集到 ECS。
- 不部署 Hive、Kafka、MLflow 或常驻 Airflow 服务。
- 不在实现和验证完成前将规划指标写入简历。

## 数据角色

自主采集数据是业务主数据，承担平台、产品、月份、评分和差评诊断。外部 Wildberries 数据是验证与补充数据，用于同商品或同品类来源对照。精选但主题不完全一致的数据只作为文本质量参照，不进入手机业务 KPI。

## 数据流

多源适配器将原始文件映射至统一数据契约。ODS 保留不可变原始快照；DWD 执行标准化、产品映射、去重、质量评分和异常隔离；DWS 生成产品、平台、月份、来源和质量主题汇总；ADS 仅生成下游实际消费的指标表。ADS 同步到 MySQL，Notebook 和 ECharts 使用同一指标口径。

## 关键接口

统一记录包含来源、批次、平台、记录类型、产品标识、评分、文本、日期、质量分、产品匹配置信度和四类指标适用性字段。每次管道运行生成 manifest，记录输入、接受、隔离、重复、耗时和门禁状态。

## 分析方法

数据源对照优先匹配相同 `nmId`，其次匹配品牌型号和品类；按产品等量抽样或加权。比较字段完整性、重复、文本长度、评分分布、负面率、主题结构和回答覆盖，并报告置信区间、效应量和分布差异。

离线管道 A/B 使用相同固定审计样本，比较现有 Pandas 管道与新 Spark 管道在有效记录识别、去重、产品映射、指标稳定性和资源开销方面的差异。

## 运行约束

Spark 在 2 核 2GB ECS 上使用本地模式和受控内存。外部大型数据在本地逐分片过滤并输出压缩 Parquet，服务器仅接收目标子集。任何缺少日期的外部数据不得进入时间趋势。

## 测试与验收

- 字段映射、日期解析、评分范围、稳定主键和质量评分均有单元测试。
- 相同批次重复运行不产生额外事实记录。
- ODS 到 DWD、DWD 到 DWS、DWS 到 ADS 均有行数或指标对账。
- 固定人工审计样本用于验证产品映射、去重和指标准入。
- 看板展示值与 ADS 输出一致。
- README 中的规模、时间范围和质量指标由运行产物生成，不手工写死。
